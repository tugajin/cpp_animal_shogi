## 3. 手法の要点 **[論文]**

### 3.1 AlphaZero 一般の説明（本論文 §2.1、pp.87–88）

- **ネットワーク**: 1つのNNが局面から **p（Policy: 合法手への確率分布）と v（Value: 期待結果、v ∈ (−1, 1)）の両方**を出力する（図1）。
- **探索（MCTS）**: 各ノード/辺に {N(s), Q(s), W(s), P(s)}（訪問回数、平均行動価値、価値合計、事前確率）を保持。選択・展開・評価・逆伝播の4ステップ（図2）。
  - 選択は **PUCT**: `PUCT = Q(c) + C·P(c)·√N(s) / (1 + N(c))`（式(1)）。C は探索と活用のバランスを取る定数。
  - 葉ノード s_L を展開し、NNで1回だけ評価して p, v を得る。p は合法手に絞って正規化し、各子への事前確率 P(c′) = p\*_{c′} とする。
  - 逆伝播で経路上の全ノードについて N(s) += 1、W(s) += v、Q(s) = W(s)/N(s) を更新。
- **自己対局での探索多様化**: ルートの事前確率に **Dirichletノイズ**を混ぜる: `p* ← (1 − ε)p* + ε·Dir(α)`（§2.1.1）。
- **学習データ**: 自己対局の各局面について、MCTSの訪問回数分布 **π** と、対局結果 **z**（z = +1 勝ち / 0 引き分け / −1 負け）を教師として保存する（§2.1.2）。
- **損失関数**（式(2)、p.88）:
  `l(θ) = (z − v)² − πᵀ log p + c‖θ‖²`
  すなわち Value の MSE（対局結果 z に対してのみ）＋ Policy の交差エントロピー（MCTSの π に対して）＋ L2正則化（c は 10⁻⁴ と読み取れる）。

### 3.2 本論文自身の実装（§3–§4・付録、pp.88–93）

- **題材**: どうぶつ将棋（4×3盤）。完全解析済みで、初期局面から到達可能な局面数は **246,803,167**。
- **入力特徴**: **18チャネル × 4 × 3**（表2）。
- **ネットワーク**（表3・表4）: 入力 [18,4,3] → 畳み込み [256,4,3] → Residualブロック（256ch）を複数積む共有部 → 2ヘッド。
  - Policy head: 出力次元 **144**（全ての指し手表現）。
  - Value head: 全結合 256 → 1、TanH、v ∈ (−1, 1)。
  - 原典 AlphaZero は Residual 19個だが、本論文では計算量の都合で **1 / 3 / 5個**を比較（教師あり学習は 1・3・5、AlphaZero学習は 3・5 と 3（Dirichletなし））。
- **評価方法**: 完全解析結果との一致率 **accuracy** を主指標とする。Value は出力の正誤（理論値との一致）、Policy は argmax_a p_a が正しい手かどうかで測る（§4.2）。第3節では強さ測定の一般論として Elo にも触れるが、実験の中心は accuracy。
- **並列化**: MCTS の並列化に **Virtual loss** を使用し、並列数は **32**（付録 A.2、参考文献 [7]）。
- **自己対局の条件**（付録 A.1.2）: GPU は GeForce GTX 1080Ti × 1。Dirichletノイズは **ε = 0.25, α = 0.34**。MCTS のシミュレーション数として 2,048、自己対局数として 10,000 という数値が付録に現れる（文脈の詳細は日本語欠落のため未確認）。先行研究 [6] の詰み探索による自己対局強化と Policy の one-hot 教師にも言及がある。
- **教師あり学習の条件**（付録 A.1.1）: 最適化は SGD（モメンタム 0.9）、バッチサイズ 2,048、GPU は GTX 1080Ti × 1。完全解析データから作った教師データで学習する。

## 4. 本論文の実験結果 **[論文]**

1. **教師あり学習（完全解析データ）では大きいネットほど良い**（図4、p.90）: 5エポックで accuracy は約 **0.966〜0.991** に到達。Residual 5 が最も高く、1 が最も低い。Value / Policy 両方で同じ傾向。
2. **AlphaZero学習では逆の結果になり得る**（図5、p.90）: iteration 1e5〜7e5 の範囲で accuracy は **0.64〜0.73程度**にとどまる。Residual 5 は 3 より悪化する条件があり、Dirichletなしの Residual 3 は Policy accuracy が学習途中で低下する。損失曲線は付録図A・1、初期局面の Value 出力の推移は付録図A・2（Dirichletなし条件では初期局面の Value が正方向へ大きくずれていく様子が見える）。
   - 学習量の目安（付録 A.1.2）: Residual 3 で自己対局 85,000局に約3.5日、Residual 5 で 80,000局に約4.5日（いずれも GTX 1080Ti × 1）。
3. **MCTS のハイパーパラメータ C は無視できない**（§4.3、図6・図7、pp.90–91）: Value出力が理論値から大きくずれる局面（図6）を題材に、学習済み Residual 3 のネットで MCTS を回し、ルートの Q(s) の推移をシミュレーション 60,000 回まで追跡。
   - 固定 **C = 1.0** では Q は単調に上がり約0.88で安定。
   - 原典方式の **C = log((N(s) + 19652 + 1) / 19652) + 1.25**（式(3)）および C = 1.5 では、Q は約35,000回で約0.85まで上がった後に **低下**し（原典方式は約0.15まで）、C = 2.0 では上昇が遅く約0.56止まり。
   - つまり同じネットでも探索側の定数だけで、探索が返す価値の質と安定性が大きく変わる。
4. **Dirichletノイズの有無は学習の成否に関わる**（付録 A.3）: AlphaZero学習では Dirichletノイズを入れた条件と入れない条件で結果が異なり、ノイズなしでは初期局面の Value 学習がうまく進まないことが示唆される（図A・1、図A・2、図5の比較から）。

## 5. cpp_animal_shogi との差分

プロジェクト側の事実は `EXPERIMENT.md` / `learn/single_network.py` による。

| 要素 | 本論文（AlphaZero系） | cpp_animal_shogi（現行） |
|---|---|---|
| ネットワーク | Policy + Value の2ヘッド、256ch、入力18ch、Residual 1/3/5 | **Value-only**（Policy headなし）、192ch、入力42ch、Residual 3、FC 256、tanh |
| 探索 | PUCTによる MCTS、事前確率 P で誘導 | **UBFM**（ミニマックス型ベストファースト）、po_num = 100 |
| 探索の教師 | 訪問回数分布 π が Policy の教師になる | 探索結果はスカラーの search_score が Value の教師になる |
| Value の教師 | 対局結果 z **のみ**（式(2)） | search_score と game_result の混合（LAMBDA = 0.5、各50%） |
| 損失 | MSE(z) ＋ 交差エントロピー(π) ＋ L2 (10⁻⁴) | MSE のみ（上記混合教師に対して） |
| 探索の多様化 | ルートへの Dirichletノイズ（ε=0.25, α=0.34） | ε-greedy 10% ＋ ランダム初期局面50% |
| 並列化 | Virtual loss、並列32 | Virtual Loss付きバッチ探索（VL_BATCH_SIZE=8）、ワーカー12 — **この点は共通** |
| 評価 | 完全解析との accuracy（Value/Policy、広い局面集合） | ans: 問題セット10,002局面（win 5,001 / lose 5,001）、閾値±0.2 |
| 完全解析データの使い方 | 教師あり学習の教師 **としても**使用し accuracy 0.97〜0.99 を記録 | 評価（オラクル照合）にのみ使用。学習への混合は未実施（`OracleDataset` は未使用） |

**数値の直接比較への注意 [考察]**: 本論文の教師あり accuracy（約0.99）と現行 ans（0.8738）は、テスト局面の集合も判定方法も異なるため、単純に「0.99 vs 0.87」とは比較できない。比較できるのは絶対値ではなく傾向（下記）である。

## 6. ans 頭打ちへの含意 **[考察]**（論文の主張ではなく、本プロジェクトへの当てはめ）

### 候補になり得るもの

1. **オラクル教師あり学習の併用 — 本論文から最も根拠が強い候補。**
   - 根拠 **[論文]**: 完全解析データを教師にした学習は、自己対局ループ（AlphaZero学習）よりはるかに高い accuracy（約0.97〜0.99 vs 約0.73）に短い学習で到達した。
   - 当てはめ: 現行の教師は search_score（自己参照的で、実験3.5では lose局面の正解率70.7%）と game_result の混合であり、「教師の質」が頭打ち要因という現行の仮説と整合する。正確な教師を混ぜることは、その仮説への直接の対処になる。
   - 留意: (a) 評価問題セット10,002局面は同じ完全解析DB由来なので、学習側から当該局面を除外しないと ans がリークで膨らむ。(b) ans の上昇が探索込みの実戦強さに直結するとは限らない。(c) 本論文でも教師あり学習は「ネットの大きさそのものの性能比較」のための別枠であり、自己対局ループへの混合比率は本論文では検証されていない。
2. **容量増は「教師あり併用とセットなら」候補。それ単独では根拠が弱い。**
   - 根拠 **[論文]**: 大きいネットほど良かったのは教師あり学習の場合のみで、AlphaZero（自己対局）学習では Residual 5 が 3 より悪化し得た。
   - 当てはめ: 現行ループ（自己対局＋自己参照教師）のまま 3→5ブロックに増やすと、本論文の自己対局側の結果と同じく改善しない可能性がある。逆に正確な教師を入れる局面では容量が効く余地がある。
3. **Value教師から search_score を外す/減らす設計は、原理面では検討に値する。ただし効果は未検証。**
   - 根拠 **[論文]**: AlphaZero の Value は対局結果 z のみから学び、探索の成果は Policy 側（π）で取り込む設計であり、探索の裏打ち値を Value に回帰させる項は存在しない。
   - 当てはめ: 現行の「モデルが自分の探索値を自分に教える」構造は実験1で既に停滞要因として自己分析されている。ただし本論文はこの ablation をしていないし、本論文の AlphaZero学習自体の accuracy は現行 ans より低い水準にとどまっており、「zのみにすれば上がる」とは言えない。LAMBDA をさらに下げる実験は、この観点では安価な検証になる。
4. **探索ハイパーパラメータは教師の質を左右する、という一般的な教訓。**
   - 根拠 **[論文]**: MCTS の C だけでルート Q が安定も崩壊もした（図7）。
   - 当てはめ: PUCT の C は UBFM に対応物がないので移植はできない。しかし「po_num を上げても変わらなかった（実験1）＝探索側は無関係」と結論づけるのは早い。UBFM 側にも教師品質を左右する設定（裏打ちの安定性など）が残っている可能性はある。優先度は教師そのものの改善より下。

### 候補になりにくいもの

5. **AlphaZero への全面移行（Policy head + PUCT の新規実装）— 本論文はむしろ慎重材料。**
   - 本論文の AlphaZero学習は、どうぶつ将棋ですら accuracy 約0.73止まりで、85,000局に約3.5日（GTX 1080Ti）を要した。現行は既に ans 0.8738 に到達しており、全面移行がこれを上回る保証は本論文のどこにもない。実装コスト（PUCT探索の新規実装、π教師の保存、損失の作り替え）も最大級である。
   - Policy head 自体は「探索の誘導」と「手の分布という追加の教師信号」を与えるため中長期的には意味があり得るが、ans（Value の符号判定）を直接押し上げる仕組みではない。やるなら全面移行ではなく、まず教師側の改善で頭打ちが動くかを確認した後である。
6. **Dirichletノイズの移植 — 現行方式にはそのまま入らない。**
   - Dirichletノイズは PUCT のルート事前確率に混ぜる仕組みであり、Policy を持たない UBFM には適用先がない。現行は ε-greedy とランダム初期局面で多様化の役割を別途担っている。本論文が示すのは「多様化の仕組みの有無が Value 学習の安定性を左右し得る」という点までで、現行の多様化が不足している証拠ではない。
7. **temperature / resign の導入 — 本論文に根拠なし。**
   - §2 の通り、本PDFの読み取れた範囲では両者の記述を確認できなかった。原典の一般知識だけで現行への導入根拠にすることは避けるべきである。

### まとめ（優先順位の提案）**[考察]**

本論文が現行プロジェクトに対して実質的に支持するのは、新しい探索への乗り換えではなく **「正確な教師（完全解析）を学習に混ぜる」方向**である。これは調査フェーズで既に挙がっていたオラクル混合学習の候補と一致し、本論文の教師あり実験がその上限の高さを示している。逆に、ネット大型化・AlphaZero全面移行・Dirichlet移植は、本論文の結果からは ans 頭打ちの打開策として支持されない（大型化は教師あり併用時のみ条件付きで候補）。
