# 調査ラウンド2: 理論編（木学習 / WDLヘッド / 収縮の理論）

対象プログラム: どうぶつしょうぎ自己対局学習。value-only ネット + UBFM/Descent 系ベストファースト・ミニマックス探索。
現行の学習レコードは「指した局面（各手の探索のルート）のみ」で、教師は s（探索のバックアップ値）と r（対局結果）を MSE で 50/50 混合。

## 1. Athénan / 木学習（tree learning）

### 1.1 出典

- Quentin Cohen-Solal, "Learning to Play Two-Player Perfect-Information Games without Knowledge", arXiv:2008.01188 **v5 (2025-05)** **[一次]**（全文PDFを読んだ）
  - 注意: 過去ラウンドで「ジャーナル版 JMLR 27 (2026)」と記録されていたが、**v5 原稿自身の表記は "Preprint submitted to Journal of Artificial Intelligence"**（Elsevier 系）であり、JMLR 説は本セッションでは確認できなかった。
- Quentin Cohen-Solal & Tristan Cazenave, "Minimax Strikes Back", Proc. AAMAS 2023, arXiv:2012.10700v2 **[一次]**（全文PDFを読んだ）

### 1.2 木学習の正確な仕組み（2008.01188 §2.2, §3.1, Algorithm 3）

- 古典的 tree bootstrapping [同論文 ref 39] では、1局の学習データは **その対局中に構築された探索木すべての状態** D = {(s, v(s)) | s ∈ T}。
- Cohen-Solal の適応版は古典版と2点異なる:
  1. **学習は各探索後ではなく、各対局の終了後に1回だけ**行う。
  2. **木の非終端リーフは学習対象から除外する**。学習集合 S は「非リーフであるか、終端である状態」の集合（Algorithm 3 のキャプション明記）。理由として論文は「データ量の大幅削減」と「overlearning effect の回避」を挙げる。リーフの値はネット自身の生出力 fθ(s) そのもので探索情報ゼロであり、そこを学ぶのは自己模倣にしかならない、というのが構造的な読みである。
- **各状態の教師 v(s) は、部分ゲーム木におけるその状態のミニマックス値**である。リーフは fθ、終端状態は ft（ゲーム利得 bt、または強化ヒューリスティクス hr、§1.5）で評価され、それがバックアップされたもの。**対局結果そのものではない**（結果だけを教師にする方式は "terminal learning" として別アームで比較され、最下位だった。§1.6）。
- 木とトランスポジションテーブル (S, T) は**1局の間ずっと保持・拡張され続け**、データセットは対局終了時点の木から作られる。途中の探索でリーフだった状態も、後続の探索で展開されれば内部ノードとして学習対象に入る。対局終了時点でなお非終端リーフのままの状態だけが捨てられる。UBFM/Descent は αβ のような剪定をしないので「剪定された部分」という概念自体がないが、リーフ除外がそれに相当する扱いになる。
- その上に経験再生が載る: Minimax Strikes Back の実験では**直近100局分のみ保持**し、smooth/stratified experience replay（µ=100, δ=3）でサンプリングする。
- データ量の帰結: AlphaZero/Polygames は「1探索あたり学習ターゲット1個」だが Athénan は「1探索あたり複数個」になるため、**学習データ生成コストは約296倍低い**（Minimax Strikes Back アブストラクト）。

**どうぶつへの含意**: 現行プログラムは root learning（指した局面のみ）であり、Athénan の主張する最大のレバー（木学習）は未導入。導入する場合の正確な仕様は「各対局の全探索木の内部ノード＋終端ノードを、その時点のバックアップ値で記録し、非終端リーフは捨てる」。現行 C++ は USE_DESCENT=false でルートのみ記録しているので、記録対象の拡張が実装の中心になる。ただし §1.6 の通り、木学習の効果は探索アルゴリズム依存（MCTS では逆効果だった）であり、UBFM/Descent 系でこそ効くという条件付きの主張である。

### 1.3 Descent と UBFM の正確な違い（2008.01188 §4.1, Algorithm 9 / 2012.10700 Algorithm 1）

- **UBFM の1イテレーション**: 現在の部分木の主変化（principal variation）上のリーフを1つだけ拡張し、評価してミニマックス・バックアップする。
- **Descent の1イテレーション**: ルートから現在の子価値の argmax/argmin（best action）を再帰的にたどり、**終端状態に到達するまで**降りていく。途中の未展開ノードでは全子を fθ で評価し（終端の子は ft で評価）、終端の正確な値をパス上にバックアップする。時間予算 τ が切れるまで繰り返す。
- 論文の言葉では「Descent is almost identical to UBFM. The only difference is that Descent performs an iteration until reaching a terminal state while UBFM performs this iteration until reaching a leaf of the tree」。
- **学習に Descent が良い理由**（論文の主張）:
  1. 各イテレーションで少なくとも1つの**正確な終端値**が木に入り、貪欲パスを伝って浅い状態まで素早く伝播する（「終端ノードの値を他のノードへ素早く引き上げる」）。
  2. 生成される状態が最善応答ライン上にあり終端に近いため、そのバックアップ値は近似として質が高い。
  3. 木学習との相乗効果が前提。Remark 6: 「Descent は時間の大半を学習のためだけに存在する状態の探索に使うので、root learning や terminal learning と組み合わせても意味がない」。
- **対局には UBFM_s**（Minimax Strikes Back §2.3.1）: UBFM_s = "Unbounded Minimax with Safe decision"。探索自体は UBFM と同一だが、**指し手は最良値の手ではなく「最も探索された手」（部分木が最も拡張されたルートの子）を選ぶ**。原典 [10] の実験で、対戦用としては UBFM_s > UBFM > αβ、学習用としては Descent > UBFM という分離が示され、「ゲームに勝つための最良の探索」と「速く学ぶための最良の探索」は別の問いだと明言されている。

**どうぶつへの含意**: (a) 現行プログラムは生成・対局とも UBFM 型で、Descent 型の「終端まで降りるイテレーション」は未使用。どうぶつは平均約21手と短く、Descent イテレーションのコストが相対的に安いゲームなので、生成側だけ Descent 化する検証は原典の主張に最も直接対応する。(b) 対局時の手選択は現行 ε-greedy 付き argmax(w) であり、UBFM_s の「最も探索された手」方式は未検証の選択肢。

### 1.4 Completion の役割（2008.01188 §5）

- 各状態に2つの補助値を付ける:
  - **completion value c(s)**: 終端結果だけのミニマックス・バックアップ。リーフでは終端勝ち +1 / 引分 0 / 終端負け −1 / 非終端 0。内部ノードでは子の c のミニマックス。
  - **resolution value r(s)**: リーフは終端なら1、非終端なら0。内部ノードは |c(s)|=1 なら1、そうでなければ子の r の最小値。要するに「その部分木が完全に解けているか」のフラグ。
- 状態比較を v 単体から **辞書順 (c, v)** に変える。これにより「解決済みの勝ち」はどんな未解決の高評価よりも常に優先される。探索中の手選択では最良の**未解決**の手を優先し（探索を続けるため）、対局時の completed action selection では「解決済みの負けに進む手を（可能なら）決して指さない」。
- 役割: completion なしでは UBFM/Descent は**非最適な不動点に陥りうる**（高評価だが未解決の状態が、証明済みの勝ちより選ばれ続ける）。completion 付きでは十分な時間で最適戦略に到達することが証明されている（Cohen-Solal, "Completeness of unbounded best-first game algorithms", arXiv:2109.09468 **[引用内]**）。
- 効果量: UBFM の勝率 +6% ± 0.7%。ただしこの数値は原典 [35]（Cohen-Solal & Cazenave, "On some improvements to unbounded minimax", arXiv preprint 2025）からの引用で、**2008.01188 自身では評価していない**（Remark 8 明記）**[引用内]**。

**どうぶつへの含意**: 現行 UBFM は completion の「部分的・手選択のみ」版を実装済み — 解決済みの子には score_win/lose ≈ ±(0.9999 − ply/2000) を与え、choice_best_move_e_greedy で優先する。しかし**バックアップされる w 自体は通常のスカラー・ミニマックスで (c, v) 辞書順ではない**し、詰み解決は mate 5手/mated 4手まで。検証として「ルートの w が、解決済み勝ちの子より未解決の子を上位に置いている局面の割合（completion 違反率）」はオラクル照合で直接数えられる。

### 1.5 強化ヒューリスティクス（win fast / lose slow）（2008.01188 §6）

- 定義: 学習中に終端状態を評価する関数 ft を、ゲーム利得 bt ∈ {+1, 0, −1} から、**bt の順序を保存する**より表現力の高い関数 hr に置き換えること。終端値が変わるため、木学習の全ターゲットと対局自体が変わる。
- **深さヒューリスティクス**（勝ちは速く、負けは遅く）:
  - 加算版 pt: 終端値 = ±l、ただし **l = P − p + 1**（P = ゲームの最大手数、p = 対局開始からの手数）。
  - 乗算版 pt′: l = P′ / p（P′ は平均対局長程度の定数）。
  - その他: scoring（ゲーム固有のスコア、オセロなら石差）、cumulative mobility（着手可能手数の平均）、presence（駒数差）。
- 効果量（§6.3、Descent+completion 固定、9ゲーム、各セル最大約27,648対局）: **古典利得 bt は平均最下位（平均勝率 40.3%、9ゲーム中7ゲームで最悪水準）**。加算深さは平均 54.9%（**古典比 +15pt**）、最良の深さヒューリスティクスで +19pt。自然なスコアがあるゲームでは scoring が最良（該当ゲーム平均 69.1%）。

**どうぶつへの含意**: 現行の解決済みスコア 0.9999 − ply/2000 は深さ項を持つが、その振幅は 200手でも 0.1 に過ぎず、r は完全に ±1 フラット。Cohen-Solal 流に振幅を大きくした版（例: 勝ち at p 手 → 1 − p/P̃、P̃ は実測最大対局長）は、s の解決済みスコアと r の両方に適用でき、学習速度（世代あたりの audit A/C の伸び）で測れる。どうぶつには自然なスコアは存在しない（ライオン捕獲で即終了）ため、適用候補は深さヒューリスティクスのみ。

### 1.6 木学習と探索アルゴリズムの効果分離アブレーション（2008.01188 §3.4, §4.2）

- **データ選択のアブレーション**（§3.4、探索 ∈ {反復深化αβ (ID), MCTS} × データ ∈ {木, root, terminal}、ε-greedy、古典利得、最終勝率の平均）:
  - ID+木 **70.7%** / MCTS+root 61.6% / MCTS+木 53.1% / ID+root 38.5% / MCTS+terminal 30.8% / ID+terminal 29.7%
  - → 木学習の効果は**探索依存**: ID では root 比 +32pt、MCTS では root 比 −8.5pt（逆効果）。**terminal learning（結果のみ教師 ≒ r のみ）は両探索で最下位級**。
- **探索のアブレーション**（§4.2、木学習に固定）: Descent+木は全組合せ相手に平均 **82%** 勝率。UBFM+木が2位で Descent はそれに **+18pt**、ID+木は −34pt。→ 木学習を固定した上での Descent 化の寄与は約 +18pt。
- 注意: これらは同一実験内の他組合せとの総当たり勝率であり、固定参照相手への Elo ではない。95% CI は ±0.85〜1.04pt 程度。

**どうぶつへの含意**: 実験設計では「木学習の導入」と「生成探索の Descent 化」を**別アーム**に分けるべきだという直接の根拠になる。混ぜて導入すると原典の数値（+32pt 級と +18pt 級）との対応が取れなくなる。また「r のみ教師」は原典で最下位であり、現行の 50/50 混合を r 寄りに倒す方向（LAMBDA 低下）は原典の結果と逆向きである点に注意。

## 2. W/D/L カテゴリカル価値ヘッドと KataGo の短期価値ターゲット

### 2.1 Lc0 の WDL ヘッド

- 出典: Leela Chess Zero 公式ブログ、crem, "Win-Draw-Loss evaluation", 2020-04-20, https://lczero.org/blog/2020/04/wdl-head/ **[一次]**（本文を読んだ）。および Lc0 開発ドキュメント "AlphaZero Primer" **[一次]**。
- 仕組み: **2019年7月以降の全 Lc0 ネットは WDL ヘッドを持つ**。3つの softmax 出力で勝ち・引分・負けの確率を別々に予測し、対局結果に対する cross-entropy で学習する。探索が使うスカラー Q は Q = W − L（最も単純な変換式）で導出する。
- ブログの動機づけ: スカラーの期待スコアは **P(draw)=1 の「死に引分」と P(win)=P(loss)=0.5 の「激しい互角」を区別できない**（どちらも 0）。引分の情報はスカラー化で破壊される。
- 正直な留保: このブログは評価表示のための記事であり、**学習アブレーションではない**。「WDL 化で学習が良くなった」という主張はこの一次資料にはない。

### 2.2 KataGo の価値ヘッド（カテゴリカル＋不確実性）

- 出典: David J. Wu, "Accelerating Self-Play Learning in Go", arXiv:1902.10565, Appendix A.5（価値ヘッド）・Appendix B（損失） **[一次]**（全文PDFを読んだ）。
- 仕組み: game-outcome サブヘッドの最初の3出力は **{win, loss, no result} の softmax ロジット**。損失は one-hot の対局結果に対する cross-entropy（重み c_value = 1.5）。加えて最終スコア差の平均 µ̂_s と標準偏差 σ̂_s を出力し、**第6〜9出力は「異なるプレイアウト数における MCTS ルート値の期待分散」の予測**、つまり局面ごとの不確実性の予測を最初からヘッドに組み込んでいる。探索用のスカラー値はこの分布から導出される。
- つまり最強級の Go 実装は最初から「スカラー MSE」ではなく「カテゴリカル分布＋補助統計量」を採用している。

### 2.3 「カテゴリカルはスカラー MSE より良く学ぶ」ことの論文証拠

- Johannes Czech, Jannis Blüml, Kristian Kersting, Hedinn Steingrimsson, "Representation Matters for Mastering Chess: Improved Feature Representation in AlphaZero Outperforms Switching to Transformers", arXiv:2304.14918v2 (2024), Table 5 **[一次]**（全文PDFを読んだ）:
  - 100万局超の人間棋譜での**教師あり** AlphaZero 型学習で、スカラー MSE 価値ヘッド vs **WDLP ヘッド**（WDL cross-entropy ＋ 残り手数ヘッド）を比較。value loss 0.4406 → **0.4356**、**+33.2 ± 19.0 Elo**。
  - 留保: (a) 自己対局ではなく教師あり。(b) WDLP は WDL と「残り手数」補助ヘッドの抱き合わせで、**WDL 単独の寄与は分離されていない**。
- Marc G. Bellemare, Will Dabney, Rémi Munos, "A Distributional Perspective on Reinforcement Learning", ICML 2017 (C51) **[一次（書誌確認）]**:
  - 返報の期待値（スカラー）を学ぶ代わりに **51カテゴリの分布を cross-entropy で学ぶ**方が Atari で state-of-the-art になった、という「カテゴリカルな価値表現は平均だけより学習信号が豊か」という主張の原典。ただし単一エージェント Atari の話で、引分のある二人ゲームではない。類比としての証拠。

**どうぶつへの含意**: 圧縮問題との接続が直接ある。スカラー MSE では「引分濃厚」と「勝敗五分」が同じ 0 に潰れ、先手劣勢でも「負け濃厚だが引分も残る」局面と「完敗」局面が同じターゲットに寄せられる。3方向 softmax ヘッドなら P(draw) が未決の質量を吸収し、導出スカラー W−L の順序情報が残る余地がある。検証設計: 現行と同一データで (a) スカラー 50/50 MSE、(b) 3方向ヘッド（主: r の one-hot に cross-entropy、補助: s から作るソフト分布）を学習し、audit の A/B（特に draw セルと lose セル）と verify_bias の対称性指数で判定する。Czech らの数値は「教師あり・抱き合わせ」の条件付きなので、ここでの A/B が初めての自己対局条件での分離測定になる。

### 2.4 KataGo の短期価値ターゲット（short-term value targets）

- 出典: David Wu, KataGo 公式ドキュメント "KataGoMethods.md"（GitHub lightvector/KataGo）, "Short-term Value and Score Targets" 節 **[一次]**（著者自身の文書を読んだ）。2020年1〜6月の "g170" ランから使用。
- **正確な構成**: 記録された対局の手 t について、補助ターゲットは将来の MCTS ルート値の指数加重平均
  `target(t) = (1−λ) Σ_{t'≥t} λ^(t'−t) · MCTS_value(t')`
  λ は3種類で、平均ホライズンは 19×19 で**約6手・16手・50手先**（小さい盤では面積比で短くする）。スコア版の補助ターゲットも同様。主ヘッドは最終対局結果（λ→1 の極限に相当）。
- **著者の述べる目的**: 「これらの補助ターゲットは低い分散のフィードバックを与える。古典的なバイアス・分散トレードオフ」— 二値の結果1個は分散が大きく、探索値の短期平均はバイアス（現ネットの探索値への依存）と引き換えに分散を下げる。著者の評価は「ネットは少し速く学習し、主ヘッドの value loss も少し良くなるようだ」。
- **著者自身の留保**: 「最近のネットで厳密に再検証されていない」。2022年の部分テストは損失の重み配分の比較図に過ぎず、**結果のみを教師にする対照群がない**。効果量は未確定と明記すべき **[一次の自己申告]**。
- 関連: 同文書の "Uncertainty-Weighted MCTS Playouts" では、ネットが**短期予測と将来 MCTS 値との二乗誤差の期待値**まで予測し（Huber 損失で学習）、不確実なプレイアウトを MCTS 内で割り引く。v1.9.0 で dynamic cPUCT と合わせて約 +50〜75 Elo と著者は報告（著者報告値、第三者検証なし）。

**どうぶつへの含意**: 現行の「1ヘッドで s と r を 50/50 平均」は、KataGo 方式では「主ヘッド = r、補助ヘッド = 将来 s の指数平均（複数ホライズン）」という**非対称な分離**に対応する。どうぶつの平均対局長は約21手なので、ホライズンは Go の面積比をそのまま適用すると1手未満になり無意味 — 対局長比で縮める（例: 約2手・5手・12手）のが妥当な設計判断として明示すべき点。検証は §2.3 の (b) アームに補助ヘッドとして組み込む形が自然。

## 3. ラベルノイズと回帰収縮（shrinkage）

### 3.1 仕組みの正確なところ

- **MSE 回帰の最適解は条件付き期待値** E[t|x]（Bishop, *Pattern Recognition and Machine Learning*, §1.5.5 **[知識]**）。したがって教師 t = (s+r)/2 のとき、ネットの到達点は E[(s+r)/2 | x] でしかない。実験4.5の実測（先手劣勢セル: s の平均 −0.595、r は −1、モデルの平均 −0.535）を見ると、混合ターゲット自体の期待値は約 −0.8 であり、モデルはそこからさらに 0 側に寄っている。**「圧縮」の少なくとも一部は学習の失敗ではなく、混合ターゲットの算術的帰結**である。
- **正則化による収縮は信号の弱い方向ほど強い**。リッジ回帰では主成分方向 j の収縮係数は d_j²/(d_j²+λ)（Hoerl & Kennard 1970; Hastie, Tibshirani & Friedman, *The Elements of Statistical Learning*, §3.4.1 **[知識]** — 本セッションで原書PDFにアクセスできなかったため未再読）。教師同士が 37〜39% 不一致する局面クラス（先手劣勢）は信号対ノイズ比が低く、重み減衰（現行 AdamW が担う λ）による収縮を最も強く受ける、というのが観測された非対称圧縮の標準理論側の説明になる。
- 注意: ノイズが教師側だけにあり容量・データが無限なら、MSE の最適解はノイズの大きさによらず E[t|x] で偏らない。収縮が「局面タイプ依存」に現れるのは、(a) ターゲット自体が混合で系統的に潰れている、(b) 有限容量＋正則化＋早期停止、(c) tanh 出力の飽和、の複合である。単一原因に帰すのは誤り。

### 3.2 実務で使われている対処法（一次資料）

1. **ヘテロスケダスティック損失（ノイズの大きい観測を自動で割り引く）**
   - David A. Nix & Andreas S. Weigend, "Estimating the mean and variance of the target probability distribution", Proc. IEEE ICNN 1994, pp. 55–60 **[一次（Kendall & Gal の参考文献で書誌確認）]**: ネットに平均と分散の2出力を付け、最尤（負の対数尤度）で学習する古典。
   - Alex Kendall & Yarin Gal, "What Uncertainties Do We Need in Bayesian Deep Learning for Computer Vision?", NeurIPS 2017, arXiv:1703.04977 **[一次]**（全文PDFを読んだ）: 損失は
     `L = mean_i [ ||y_i − f(x_i)||² / (2σ(x_i)²) + (1/2) log σ(x_i)² ]`
     第1項が「learned loss attenuation」で、ノイズの大きい入力ほど自動的に重みが下がる。第2項が σ→∞ への崩壊を防ぐ。
2. **誤差の大きいサンプルの重点サンプリング**
   - Tom Schaul, John Quan, Ioannis Antonoglou, David Silver, "Prioritized Experience Replay", ICLR 2016, arXiv:1511.05952 **[一次（書誌確認）]**: |TD誤差| に比例したサンプリング＋重要度補正。ゲームAIへの移転形として「教師不一致 |s−r| の大きい局面の過剰サンプリング/重み付け」が対応する（オラクル不要で測れる）。
3. **重複ラベルの平均化**
   - 同一局面の独立なノイズ付きラベル n 個の平均は分散が 1/n になる（初等的統計）。本プロジェクトではレコードの 50.5% が重複局面であり、現行は別サンプルとしてそのまま学習している。局面ごとに s と r を平均して1レコード化するのはコストゼロの分散削減になる（dlshogi が同趣旨の処理をしていることは前ラウンドのブログ調査で確認済み **[二次・実務家資料]**）。
4. **ターゲット自体の分散削減**
   - KataGo の短期価値ターゲット（§2.4）は「単一の二値結果」より「探索値の指数平均」の方が低分散だという発想そのもの。また KataGo の不確実性ヘッド（§2.2, §2.4）はヘテロスケダスティック発想のゲームAI実装で、局面ごとに「自分の予測の二乗誤差の期待値」を予測させ、探索側で割り引く。

### 3.3 どうぶつでの検証設計への落とし込み

- **まず測る**: 既存データの重複局面について、出現ごとの s の分散をオラクルカテゴリ別に集計する。これが「局面タイプ別の教師ノイズ」の直接測定になり、収縮が起きるはずの場所の予測と、verify_bias の実測バイアスの対応を検証できる。
- **実験アーム（同一データ・同一初期値）**: (a) 現行 50/50 MSE、(b) 重複ラベル平均化のみ、(c) ヘテロスケダスティック損失（σ は重複分散か |s−r| から与える簡易版でも可）、(d) |s−r| 重み付けサンプリング。判定は ans ではなく audit A/C と対称性指数。
- **解釈の注意**: (a) の収縮がターゲット混合の算術なら、(b)〜(d) では消えず、効くのは §2 の「主 = r、補助 = s」型の非対称設計のはず。検証順序として、収縮の原因分解（ターゲット起因 vs 学習起因）を先にやる価値がある。分解方法: 学習済みモデルの出力と「混合ターゲットの条件付き平均の実測値（重複局面の平均ターゲット）」を局面クラス別に比べる。モデル ≈ 実測平均なら学習側は正常で、問題はターゲット設計にある。
