## Q2. 同定の精度（オラクル照合、評価専用）

- 照合できた候補: 42,231 件（未登録 366 件）
- **オラクルと一致: 42,119 件（99.73%）** / 不一致: 112 件
- 不一致の例（key, s, オラクルの手番側ラベル）: [(155743769741436928, 0.8999, 0), (155728380323639296, 0.8999, 0), (155728380248617088, 0.8999, 0), (155728380256481409, -0.8999, 0), (155728436627927168, 0.8999, 0)]

読み方: 一致率が 99% 以上なら同定は実用になる。不一致が多い場合は、格子一致が偶然か、証明値の伝播方法の想定（バックアップで値がそのまま伝わる）が間違っている。

## Q5. 証明レコードでの r 汚染

- r が記録されている証明候補: 50,090 件
- r と s が符号不一致: 907 件（1.8%） / r=0（引き分け）: 13 件（0.0%）
- 混合教師の証明値からのずれ |(s+r)/2 − s|: 全体平均 0.0239 / 符号不一致のみ平均 0.9509

読み方: 証明局面では s が正解なので、混合教師のずれはそのまま r 項が注入する誤差。符号不一致率が高ければ「証明レコードでは r 項を切る」arm の利得が大きい。

## Q6. k 分布のスパイク（クランプ混入チェック）

- k=197〜203 の候補数: {197: 1, 198: 3, 199: 1, 200: 5479, 201: 2, 202: 0, 203: 0}
- 候補数が多い k: [(2, 20497), (1, 11257), (3, 9106)]
- Q2 不一致の k 分布（上位）: [(200, 70), (678, 4), (4, 3), (954, 3), (840, 2)]

読み方: predict のクランプ（|出力|≥1 → ±0.8999）は格子点 k=200 と正確に一致する。k=200 にスパイクがあり不一致も k=200 に集中するなら、k=200 の候補は証明ではなく飽和した推定値の混入であり、同定からは k=200 を除外すべき（po=100 では深さ200の証明木は作れない）。

## Q4. モデルの再現度（証明ラベル候補 vs 推定ラベル）

- 証明ラベル候補: 10,000 局面 / |v − s| 平均 0.0586 / 中央値 0.0011 / 符号一致 98.2%
- 推定ラベル（|s|>0.5）: 10,000 局面 / |v − s| 平均 0.2420 / 中央値 0.1003 / 符号一致 91.7%

読み方: 証明ラベル候補で |v − s| が大きいなら、正確なラベルが付いている局面ですらモデルが再現できておらず、確信度層別（証明ラベルへの高重み付け）に意味がある。逆にほぼ 0 なら、証明ラベルは既に学習され切っていて層別の利得は小さい。

## 判定

- 候補が全レコードの数% 以上あり、Q2 の一致率が 99% 以上なら「証明ラベルの同定」は成立し、確信度層別学習（証明レコードでは r 項を切り、s を高重みにする）の arm 化に進める
- 候補が僅少、または一致率が低い場合は、この手法は不成立として下げる
