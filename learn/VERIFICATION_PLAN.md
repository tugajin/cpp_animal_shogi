## 0. 確定した事実（土台）

### ソースから
- 生成: 平手50%/ランダム開始50%、po_num=100（葉評価回数の上限、通常局面ではほぼ消化）、ε-greedy 10%
- 教師 s = ルート w。バックアップは**硬いミニマックス**（update_node は max のみ、平均化なし）→ 主変化の葉1枚の誤差がルート値に直通する
- 証明の優先は update_node に実装済み（2026-11-20 再確認）: 子が解決済み負けなら即座にそのノードは勝ちとして確定し推定値の兄弟は見ない。全子が解決済み勝ちなら負け（最も遅い負けを選択＝lose-slow）、引き分けと負けのみなら引き分け確定。未解決の場合のみ推定値の max を取る。残る論点は「ルートが解決済みだったかどうかが学習レコードに保存されない」ことだけで、バックアップの欠陥ではない
- 詰み探索はノード評価に組み込み済み（王手なし: mate 5手 / 王手時: mated 4手）。ただし発火率（生成時にどれだけ効いているか）は未測定
- 特徴量42chに**履歴情報なし**（手数・出現回数なし）。千日手はモデルに見えない
- 学習はオプティマイザ状態ごと引き継ぐ継続学習。記録はルート局面のみ、重複は平均化されずそのまま（重複率 50.5%）
- USE_DESCENT=true 側に木全体を記録する add_replay_buffer が存在するが未使用。ただし葉も記録する実装で、Athénan の記録規則（葉は除外）とは異なる

### 測定から
- 順序は健全（audit B 87.7%）。損失は win 変換（維持 89.5%、→lose 3.6%）と draw 保持（84.2%）、後手番の弱さに集中
- 探索の上乗せ C−A ≈ 0（po=100 の探索はモデル単体の argmax をほぼ改善しない）
- 教師の非対称: 探索の正解率は先手勝ち局面 93–95% vs 先手負け局面 60–67%。教師同士の不一致 37–39%
- 圧縮: 先手劣勢で平均値が −0.59 級に縮む。ただし混合教師の条件付き平均 E[(s+r)/2] 自体が ≈ −0.8 であり、モデルの −0.535 との差が「学習側の縮み」分

### 文献から
- Athénan: 木学習（非葉＋終端の状態を裏打ち値で学習）が最大の係数。結果のみの学習（terminal learning）は最悪。Descent は UBFM より学習向き（木学習固定で +18pt）。証明優先（completion）なしの UBFM/Descent は不完全
- KataGo: 主ターゲットは結果、探索値は「将来の探索値の指数平均」という短期補助ターゲット。予算は混合（playout cap randomization）が一律に全勝。surprise 重み付け（探索とネットの不一致局面を厚く）
- dlshogi: 教師の付け替え（モデル推論側へ 0.9 ブレンド）が深い探索ラベルそのままを上回った。「読めないモデルには学習が難しい」。生成側では正確な終局判定が NN 値を上書きし、長手数の引き分け対局レコードは既定で破棄される
- GPW2020 soft value: **正確な期待値ですら終盤から遠い局面では 0 側に圧縮される**。圧縮は欠陥とは限らない。効いたのは「結果を維持できる手の数」を織り込んだ値で、相手の安全手を奪う指し回しになった
- GPW2025（Mini-2048）: **対称拡張が値の過大評価を誘発した**実例。拡張 arm には符号付きバイアスの監視が必須
- 測定論: 300戦では ±39 Elo の信頼区間しか得られない。audit（3,000局面で SE ≈ 0.9%）が主指標、対戦は先後入替の補助確認に留めるのが合理的

## 1. 仮説と検証

### H1: 教師 s のノイズが主ボトルネック（葉誤差の直通）
根拠: 硬いミニマックス、教師正解率の非対称、C−A ≈ 0。
検証（学習なし）:
- **V1a PO サーモメーター改訂版**: 固定局面で po=100/400/1600 を回し、s のオラクル一致率、C−A、**詰み探索の発火率**、解決済みになる局面の割合を同時に測る。po で発火率と解決率が伸びるなら「読み切り」が律速。伸びないなら葉の質が律速
- ~~V1b completion 違反率~~ **削除（2026-11-20）**: update_node を最後まで読み直した結果、証明の優先は実装済みだった（子が解決済み負けなら即確定、全子解決済み勝ちなら最も遅い負けを選ぶ）。「証明済みの勝ちが推定値に負ける」事象はこの実装では起きない
- **V1c 教師ノイズ地図**: 重複局面の s の分散をカテゴリ別に測る（同一局面への複数サンプルが既存データにある）。ノイズの大きいセルが漏れセルと一致するか

### H2: 圧縮は「教師の平均＋shrinkage」であって学習の失敗ではない
検証（既存データの再集計のみ）:
- **V2 圧縮の分解**: 重複局面ごとに混合教師の条件付き平均を計算し、モデルの出力と比較する。モデル ≈ 条件付き平均なら、圧縮は目標関数の算術であり、直すなら教師設計（H3）であって学習側ではない

### H3: 教師の「混ぜ方」が lose セルで両教師以下を生んでいる
根拠: 実験4.5 結論4（平均化でモデルが両教師以下）、Athénan（結果のみは最悪＝s が主であるべき）、KataGo（主=r・補助=s の非対称）、dlshogi（val_lambda=1/3、付け替え 0.9）。
検証（同一データでの短期学習 arm、判定は audit A/C と対称性指数）:
- **V3a 短期ターゲット（生成コストゼロ）**: 既存レコードは対局順に s_t が並んでいるので、KataGo 式の「将来の s の指数平均」を後付けで計算できる。これを補助/代替ターゲットにした arm
- **V3b ラベル平均化**: 重複局面の s・r を平均してから学習する arm（dlshogi 方式）。分散は 1/n で下がる
- **V3c 混合比と非対称**: LAMBDA ∈ {0.25, 0.5, 0.75} の単独スイープ。非対称（主・補助）構成は2ヘッド化が要るため、比率スイープの結果を見てから判断
- **V3d surprise 重み付け**: |s − r| または |s − v_model| が大きい局面の重みを上げる arm（PER / KataGo の読み替え、オラクル不要）

### H4: 記録の「量の質」— 木学習で情報密度を上げる
根拠: Athénan の最大係数。現行は1手につき1局面しか記録していない。
検証（生成側の変更を伴う中コスト）:
- **V4 木学習 arm**: add_replay_buffer を Athénan の規則（非葉＋終端のみ、葉は除外）に直して記録し、s のみで学習する arm（r は木の状態には対応付けない。paper の terminal learning 最悪という結果と、現行の混合損失の両に配慮し、まず s 単独で測る）。データ量の倍率と audit の変化を測る
- 注意: 現行の search_descent は VL バッチ型の UBFM であり、Cohen-Solal の Descent（毎回終端まで辿る）とは別物。探索自体の Descent 化は別の大きな変更として切り分け、V4 では記録だけを変える

### H5: 漏れは「壊れやすい局面」に集中している
根拠: soft value 論文（維持できる手の数が本質）、GPW2022（最善手と最悪手の差が大きい局面への集中が効く）。
検証（audit データの再集計のみ）:
- **V5 脆弱性層別**: audit の各局面について「最良カテゴリを達成できる手の数」で層別し、失敗率が単一手しかない局面に集中しているかを見る。集中していれば、生成・重み付けでその局面型を厚くする根拠になる

### H6: 引き分けレコードが r を汚している
根拠: 実験4終盤で引き分けが急増（128、85）。dlshogi は長手数引き分けのレコードを破棄する。理論上 draw の局面でも実戦結果 r は ±1 になりがちで（実験3.5: draw 局面での game_result 正解率 6.2%）、draw セルの教師として r はほぼノイズ。
検証（既存データの再集計→短期学習 arm）:
- **V6a** 引き分け対局由来レコードの割合と、その r と局面カテゴリの一致率を測る
- **V6b** 引き分け対局のレコードを除外/減重した arm を audit の draw 維持率で判定

### H7: 対称拡張（実験5-V1 として先行していた項目）— 保留に格下げ
理由: 文献に効果量がなく、GPW2025 に対称拡張が過大評価を誘発した実例がある。やる場合は符号付きバイアス（V7: 拡張前後での平均値ドリフト）を監視指標に入れることが条件。検証3（ツイン診断）の結果が大きい場合のみ昇格させる。

## 2. 実施順と判定の接続

- **フェーズ0（再集計のみ・最安）**: V2（圧縮分解）、V5（脆弱性層別）、V6a（引き分け汚染）、V1c（教師ノイズ地図）、V3a のターゲット計算可能性の確認
  → ここで「教師設計の問題か、データの問題か」の大枠が決まる
- **フェーズ1（エンジン実行・学習なし）**: V1a（PO＋発火率）、ツイン診断
  → PO・詰み深さのどちらが生成側レバーか決まる
- **フェーズ2（短期学習 arm）**: V3b → V3a → V3c → V3d（安い順）。各 arm は同一初期値・同一データ、判定は audit A/C（win/draw 維持率）＋対称性指数＋符号付きバイアス
- **フェーズ3（生成変更）**: フェーズ1の結果で V4（木学習）または予算ミックス（KataGo 式）または詰み深化のいずれか1つ
- **実験5 本番**: フェーズ2・3 の勝ち arm を1つ（多くて2つ）だけ入れて実験4条件で回す
- **実験6 候補**: WDL 3分類ヘッド（draw の表現力。Lc0 の動機が本件と一致）、探索の Descent 化、soft value 型ターゲット（維持手数を織り込む）
