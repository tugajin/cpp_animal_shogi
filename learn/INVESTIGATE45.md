実験4（ans 最高 0.8738、記録10以降 0.8685〜0.8738 で頭打ち）の原因を切り分けるための調査。

成果物は `investigate45_result.md`。これを `EXPERIMENT.md` の「実験4.5」節に貼り、考察を書き足せば調査完了になる。

## 1. 軽量版（A+B、オラクル不要）

```bash
../.venv/bin/python investigate45.py --skip-oracle
```

- A: `problem.txt`（win 5,001 / lose 5,001）の誤答内訳 — 逆判定か未決か、win/lose の非対称、閾値感度
- B: 自己対局データ監査 — 世代ごとの件数・ユニーク率・重複、世代間の新規局面率、`search_score` の未決率、`search_score` と `game_result` の符号一致率

まずこれだけでも「未決が多いのか／逆判定が多いのか」「データがどれだけ重複・陳腐化しているか」が分かる。

## 2. フル版（C+D、オラクル使用）

```bash
../.venv/bin/python investigate45.py
```

- C: 最新世代（最大の gen_N）のデータ最大20,000件をオラクルと照合し、model / search_score / game_result の正解率を win/lose/draw 別に出す。**実験3.5の表と直接比較するための本命**
- D: オラクルから各カテゴリ10万局面サンプル（seed=42、実験3.5と同一条件）でのカテゴリ別精度

注意:
- C/D は `../data/win.dat` 等をソート済み配列として読み、二分探索で照合する。既存の `analyze_selfplay_coverage.py` は 1.97億件を Python の set 化してメモリを食い潰すので、そのまま使わないこと
- 既存の `analyze_*.py` 群は `data/*.json` の非再帰 glob で `gen_N/` を取りこぼす。個別に使う場合は再帰 glob への修正が必要（本スクリプトは修正済み）

## 3. 結果の読み方（実験5への分岐）

以下は判定の目安。単独ではなく組み合わせで判断する。

| 調査で見えたこと | 解釈 | 実験5の候補 |
|---|---|---|
| A で誤答の多くが未決（\|score\|<0.2）、閾値 0.05〜0.10 で ans が大きく上がる | スコアが 0 付近に縮んでいる。頭打ちの一部は ±0.2 という測り方の問題 | 学習側の見直し（LAMBDA、エポック数、教師のスケール）。容量増は後回し |
| A で逆判定が多く、特に lose 側に偏る | 表現力か教師の質の問題 | C の結果と合わせて判断（下の2行） |
| C で lose の search_score 正解率が実験3.5（70.7%）からほぼ改善していない | データ量では教師の質は上がらなかったことが確定 | **オラクル混合学習**（未使用の `OracleDataset` を使う）。ただし `problem.txt` の10,002局面は評価専用として学習から必ず除外する |
| C で search_score は改善したが model が追いついていない | 教師は良いが学習が吸収できていない | エポック数・学習率・データ配分の学習側実験 |
| B で最新世代の新規局面率が低い／全体の重複率が高い | 蓄積データが陳腐化し、同じ局面を繰り返し学習している（loss が記録11で反転したことと整合） | 蓄積を最新1〜2世代に絞る、または現モデルでデータを全再生成 |
| B で世代が進んでも s・r 符号一致率が低いまま | 対局結果のノイズが大きい（ε-greedy 10% の影響など） | ε の再調整、または game_result の重み（LAMBDA）の見直し |
| A〜D で大きな異常がなく、逆判定が満遍なく残る | 3ブロック/192ch の表現力の上限の可能性が残る | その場合に限り容量増（ブロック数・チャネル数）を実験5にする |
